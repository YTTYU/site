# Jagger Garage — сайт P-4

Презентационный сайт гусеничного вездехода-амфибии P-4. Astro (статическая
сборка) + GSAP/ScrollTrigger для анимаций + нативные `<details>` для
аккордеонов. Контент временно захардкожен в `src/content/data/` — Sanity
подготовлен, но не подключён (см. `sanity/README.md`).

## Запуск локально

Нужен только [Node.js](https://nodejs.org) 22+ — отдельно устанавливать Astro
не нужно, он ставится как обычная npm-зависимость вместе со всем остальным.

```bash
cd site
npm install
npm run dev
```

Откроется на `http://localhost:4321`. Если запускаете из PyCharm: откройте
терминал PyCharm (Alt+F12), перейдите в папку `site` и выполните эти же две
команды — PyCharm не запускает dev-сервер сам, ему нужна явная команда в
терминале.

Если браузер/инструмент не может достучаться до `localhost` — проверьте, что
сервер слушает и `127.0.0.1`, а не только `::1` (IPv6): `npm run dev -- --host
127.0.0.1`, либо `--host 0.0.0.0` чтобы слушать все интерфейсы.

## Сборка и предпросмотр продакшен-версии

```bash
npm run build     # → ./dist
npm run preview   # локальный предпросмотр собранной версии
```

## Структура

```
src/
├── components/
│   ├── sections/     — секции лендинга (Hero, Advantage, EngineeringHub, ...)
│   └── ui/            — шапка, футер, логотип
├── content/data/      — весь текстовый контент (copy.ts) и контакты (contacts.ts)
├── assets/images/     — исходники изображений по секциям (обрабатываются astro:assets)
├── scripts/gsap/      — общая GSAP-инфраструктура (core.ts: реестр плагинов, reveal())
└── styles/            — переменные темы, шрифты, глобальные стили
public/
├── fonts/             — сконвертированные .woff2
└── video/             — hero-source.mp4 (см. заметку про видео ниже)
sanity/                — схемы и README для будущего подключения CMS
```

## Известные незакрытые моменты

- **Шрифты.** `Core Sans D`, `PF DinDisplay Pro`, `Eurostile Extended Black`
  подключены и сконвертированы в WOFF2. `Arturito Slab Bold`, `Conthrax
  Heavy`, `Core Sans A 75 ExtraBold` — в переданных файлах их не было; сейчас
  вместо них временные заменители (см. комментарии в
  `src/styles/fonts.css` и `variables.css`, переменные `--font-slab` /
  `--font-display` / `--font-emphasis`). Когда пришлёте файлы — положите .ttf/.otf
  в любую папку, я (или вы) сконвертируете в WOFF2 и пропишете в `fonts.css`.
- **Контакты.** В `src/content/data/contacts.ts` — плейсхолдеры
  (`isPlaceholder: true`). Замените на реальные телефон/почту/соцсети, флаг
  можно убрать.
- **Видео.** `public/video/hero-source.mp4` — исходный файл без пережатия
  (нет `ffmpeg` в этом окружении). Для продакшена стоит перекодировать в
  H.264 (веб-профиль, битрейт пониже) и добавить WebM-версию — сейчас на
  мобильных вьюпортах (<720px) видео вообще не грузится, показывается только
  постер, так что до перекодирования сайт не пострадает по производительности.
- **Sanity.** Не подключён по вашему решению — см. `sanity/README.md`.
- **Форма заявки** на Контактах не подключена к почтовому провайдеру —
  сейчас просто HTML-форма без обработчика.

## Деплой

### Vercel (основной таргет)

Проект уже использует `@astrojs/vercel` (см. `astro.config.mjs`). Из
консоли Vercel: "Import Project" → указать папку `site/` как корень (Root
Directory), фреймворк определится автоматически, ничего дополнительно
настраивать не нужно.

Либо через CLI:
```bash
npm i -g vercel
cd site
vercel
```

### Netlify (альтернатива)

Тот же статический билд (`npm run build`, вывод в `dist/`) деплоится и на
Netlify без адаптера: Build command `npm run build`, Publish directory
`dist`. При желании можно завести `netlify.toml` с этими же настройками.

## Проверка производительности

Перед продакшен-релизом рекомендуется прогнать Lighthouse на собранной
версии (`npm run build && npm run preview`, затем Lighthouse на
`localhost:4321` в Chrome DevTools) — цель Performance 90+ на мобильном.
